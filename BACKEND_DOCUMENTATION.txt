================================================================================
                          2. DATABASE TABLES
================================================================================

--------------------------------------------------------------------------------
TABLE: users
--------------------------------------------------------------------------------
Purpose: Store user accounts (customers and admins)

Columns:
- id                  : Primary key (auto-increment)
- name                : User's full name (string)
- email               : User's email (unique)
- password            : Hashed password
- role                : 'customer' or 'admin' (default: customer)
- email_verified_at   : Email verification timestamp (nullable)
- remember_token      : For "remember me" functionality
- created_at          : Record creation timestamp
- updated_at          : Record update timestamp

--------------------------------------------------------------------------------
TABLE: plants
--------------------------------------------------------------------------------
Purpose: Store plant products for the shop

Columns:
- id                  : Primary key (auto-increment)
- name                : Plant name (required)
- scientific_name     : Scientific/botanical name (nullable)
- category            : Category like Indoor, Outdoor, etc. (nullable)
- difficulty          : Care difficulty - Easy, Medium, Hard (nullable)
- light               : Light requirements (nullable)
- water               : Watering frequency (nullable)
- soil                : Soil type requirements (nullable)
- description         : Detailed plant description (nullable)
- price               : Price in NPR (decimal, required)
- stock               : Available quantity (integer, required)
- image               : Image URL/path (nullable)
- is_active           : Whether plant is available for sale (boolean, default: true)
- created_at          : Record creation timestamp
- updated_at          : Record update timestamp

--------------------------------------------------------------------------------
TABLE: carts
--------------------------------------------------------------------------------
Purpose: Store shopping cart items for each user

Columns:
- id                  : Primary key (auto-increment)
- user_id             : Foreign key to users table (cascade on delete)
- plant_id            : Foreign key to plants table (cascade on delete)
- quantity            : Number of items (integer, default: 1)
- created_at          : Record creation timestamp
- updated_at          : Record update timestamp

Constraints:
- UNIQUE(user_id, plant_id) : Prevents duplicate items, updates quantity instead

--------------------------------------------------------------------------------
TABLE: orders
--------------------------------------------------------------------------------
Purpose: Store customer orders after checkout

Columns:
- id                  : Primary key (auto-increment)
- user_id             : Foreign key to users table (cascade on delete)
- status              : Order status (default: 'pending')
                        Options: pending, processing, shipped, delivered, cancelled
- subtotal            : Sum of all items before fees (decimal)
- delivery_fee        : Delivery/shipping charge (decimal, default: 0)
- tax                 : Tax amount (decimal, default: 0)
- total               : Final total amount (decimal)
- shipping_name       : Recipient name (nullable)
- shipping_phone      : Contact phone number (nullable)
- shipping_address    : Delivery address (nullable)
- created_at          : Record creation timestamp
- updated_at          : Record update timestamp

--------------------------------------------------------------------------------
TABLE: order_items
--------------------------------------------------------------------------------
Purpose: Store individual items within each order

Columns:
- id                  : Primary key (auto-increment)
- order_id            : Foreign key to orders table (cascade on delete)
- plant_id            : Foreign key to plants table (cascade on delete)
- quantity            : Number of items ordered (integer)
- price               : Price at time of order (decimal) - SNAPSHOT
- line_total          : quantity × price (decimal)
- created_at          : Record creation timestamp
- updated_at          : Record update timestamp

Note: Price is stored as a snapshot to preserve historical order data
      even if the plant price changes later.

================================================================================
                       3. AUTHENTICATION SYSTEM
================================================================================

File: app/Http/Controllers/Api/AuthController.php

--------------------------------------------------------------------------------
REGISTER - POST /api/register
--------------------------------------------------------------------------------
Purpose: Create a new user account

Request Body:
{
    "name": "string (required)",
    "email": "string (required, unique)",
    "password": "string (required, min: 6 characters)",
    "password_confirmation": "string (required, must match password)"
}

Response (201 Created):
{
    "message": "User registered successfully",
    "user": { user object },
    "token": "authentication token"
}

Process:
1. Validate input data
2. Hash the password
3. Create user with role 'customer'
4. Generate Sanctum token
5. Return user data and token

--------------------------------------------------------------------------------
LOGIN - POST /api/login
--------------------------------------------------------------------------------
Purpose: Authenticate existing user

Request Body:
{
    "email": "string (required)",
    "password": "string (required)"
}

Response (200 OK):
{
    "message": "Login successful",
    "user": { user object },
    "token": "authentication token"
}

Response (401 Unauthorized):
{
    "message": "Invalid credentials"
}

Process:
1. Validate input data
2. Find user by email
3. Verify password using Hash::check()
4. Generate new Sanctum token
5. Return user data and token

--------------------------------------------------------------------------------
LOGOUT - POST /api/logout (Requires Auth)
--------------------------------------------------------------------------------
Purpose: Invalidate current authentication token

Headers Required:
Authorization: Bearer {token}

Response (200 OK):
{
    "message": "Logged out successfully"
}

Process:
1. Get current authenticated user
2. Delete current access token
3. Return success message

--------------------------------------------------------------------------------
GET PROFILE - GET /api/me (Requires Auth)
--------------------------------------------------------------------------------
Purpose: Get current logged-in user's information

Headers Required:
Authorization: Bearer {token}

Response (200 OK):
{
    "user": { user object }
}

================================================================================
                          5. CART SYSTEM
================================================================================

File: app/Http/Controllers/Api/CartController.php

All cart routes require authentication (auth:sanctum middleware)
Each user has their own cart - users can only see/modify their own cart items

--------------------------------------------------------------------------------
VIEW CART - GET /api/cart (Requires Auth)
--------------------------------------------------------------------------------
Purpose: Get current user's cart with all items and total

Response (200 OK):
{
    "cart": [
        {
            "id": 1,
            "user_id": 1,
            "plant_id": 5,
            "quantity": 2,
            "plant": { plant object }
        },
        ...
    ],
    "total": 600
}

Process:
1. Get cart items for current user
2. Load plant relationship
3. Calculate total (sum of price × quantity)
4. Return cart items and total

--------------------------------------------------------------------------------
ADD TO CART - POST /api/cart (Requires Auth)
--------------------------------------------------------------------------------
Purpose: Add a plant to the cart

Request Body:
{
    "plant_id": "integer (required, must exist in plants table)",
    "quantity": "integer (optional, default: 1, min: 1)"
}

Response (201 Created):
{
    "message": "Added to cart",
    "cart": { cart item with plant }
}

Response (400 Bad Request):
{
    "message": "Not enough stock"
}

Process:
1. Validate plant exists
2. Check if enough stock available
3. If item already in cart → increase quantity
4. If new item → create cart entry
5. Validate total quantity against stock
6. Return updated cart item

--------------------------------------------------------------------------------
UPDATE QUANTITY - PUT /api/cart/{id} (Requires Auth)
--------------------------------------------------------------------------------
Purpose: Change quantity of a cart item

Request Body:
{
    "quantity": "integer (required, min: 1)"
}

Response (200 OK):
{
    "message": "Cart updated",
    "cart": { updated cart item }
}

Response (400 Bad Request):
{
    "message": "Not enough stock"
}

Process:
1. Find cart item (must belong to current user)
2. Check stock availability
3. Update quantity
4. Return updated cart item

--------------------------------------------------------------------------------
REMOVE ITEM - DELETE /api/cart/{id} (Requires Auth)
--------------------------------------------------------------------------------
Purpose: Remove a single item from cart

Response (200 OK):
{
    "message": "Removed from cart"
}

--------------------------------------------------------------------------------
CLEAR CART - DELETE /api/cart (Requires Auth)
--------------------------------------------------------------------------------
Purpose: Remove all items from user's cart

Response (200 OK):
{
    "message": "Cart cleared"
}

                          6. ORDER SYSTEM
================================================================================

File: app/Http/Controllers/Api/OrderController.php

--------------------------------------------------------------------------------
CHECKOUT - POST /api/checkout (Requires Auth)
--------------------------------------------------------------------------------
Purpose: Convert cart to an order

Request Body:
{
    "shipping_name": "string (optional)",
    "shipping_phone": "string (optional)",
    "shipping_address": "string (optional)"
}

Response (201 Created):
{
    "message": "Order placed successfully",
    "order": {
        "id": 1,
        "user_id": 1,
        "status": "pending",
        "subtotal": 600,
        "delivery_fee": 0,
        "tax": 0,
        "total": 600,
        "shipping_name": "John Doe",
        "shipping_phone": "9841234567",
        "shipping_address": "Kathmandu, Nepal",
        "items": [
            {
                "id": 1,
                "plant_id": 5,
                "quantity": 2,
                "price": 300,
                "line_total": 600,
                "plant": { plant object }
            }
        ]
    }
}

Response (400 Bad Request):
{
    "message": "Cart is empty"
}
OR
{
    "message": "Not enough stock for {plant name}",
    "available_stock": 5
}

Process (within database transaction):
1. Get user's cart items
2. Validate cart is not empty
3. Check stock availability for each item
4. Calculate subtotal
5. Create order record
6. Create order items (with price snapshot)
7. Reduce stock for each plant
8. Clear user's cart
9. Return order with items

--------------------------------------------------------------------------------
MY ORDERS - GET /api/orders (Requires Auth)
--------------------------------------------------------------------------------
Purpose: Get all orders for current user

Response (200 OK):
{
    "orders": [
        {
            "id": 1,
            "status": "delivered",
            "total": 600,
            "items": [...],
            ...
        },
        ...
    ]
}

--------------------------------------------------------------------------------
ORDER DETAILS - GET /api/orders/{id} (Requires Auth)
--------------------------------------------------------------------------------
Purpose: Get single order details (owner only)

Response (200 OK):
{
    "order": { order object with items }
}

Response (403 Forbidden):
{

(If trying to view another user's order)

--------------------------------------------------------------------------------
UPDATE STATUS - PUT /api/orders/{id}/status (Admin Only)
--------------------------------------------------------------------------------
Purpose: Update order status (admin only)

Request Body:
{
    "status": "string (required)"
    // Options: pending, processing, shipped, delivered, cancelled
}

Response (200 OK):
{
    "message": "Order status updated",
    "order": { updated order }
}

Response (403 Forbidden):
{
    "message": "Forbidden. Admin access required."
}
(If user is not admin)

================================================================================
                           7. MIDDLEWARE
================================================================================

--------------------------------------------------------------------------------
AUTH:SANCTUM (Laravel Built-in)
--------------------------------------------------------------------------------
File: Provided by Laravel Sanctum package

Purpose: Protect routes that require authentication

Usage in routes:
Route::middleware('auth:sanctum')->group(function () {
    // Protected routes here
});

Behavior:
- Checks for valid Bearer token in Authorization header
- Returns 401 if token is missing or invalid

--------------------------------------------------------------------------------
ADMIN MIDDLEWARE (Custom)
--------------------------------------------------------------------------------
File: app/Http/Middleware/AdminMiddleware.php

Purpose: Restrict routes to admin users only

Registration: bootstrap/app.php
$middleware->alias([
    'admin' => \App\Http\Middleware\AdminMiddleware::class,
]);

Usage in routes:
Route::middleware(['auth:sanctum', 'admin'])->group(function () {
    // Admin-only routes here
});

Behavior:
- Checks if authenticated user has role = 'admin'
- Returns 403 Forbidden if user is not admin

================================================================================
                       8. API ENDPOINTS SUMMARY
================================================================================

BASE URL: http://127.0.0.1:8000/api

--------------------------------------------------------------------------------
PUBLIC ENDPOINTS (No Auth Required)
--------------------------------------------------------------------------------
GET    /ping              → Test API connection
POST   /register          → Create new user account
POST   /login             → Login and get token

--------------------------------------------------------------------------------
AUTHENTICATED ENDPOINTS (Requires Bearer Token)
--------------------------------------------------------------------------------
POST   /logout            → Logout (invalidate token)
GET    /me                → Get current user profile

GET    /plants            → List all active plants
GET    /plants/{id}       → Get single plant
POST   /plants            → Create new plant
PUT    /plants/{id}       → Update plant
DELETE /plants/{id}       → Delete plant

GET    /cart              → View cart with total
POST   /cart              → Add item to cart
PUT    /cart/{id}         → Update cart item quantity
DELETE /cart/{id}         → Remove item from cart
DELETE /cart              → Clear entire cart

POST   /checkout          → Create order from cart
GET    /orders            → List my orders
GET    /orders/{id}       → View order details

--------------------------------------------------------------------------------
ADMIN ONLY ENDPOINTS (Requires Admin Role)
--------------------------------------------------------------------------------
PUT    /orders/{id}/status → Update order status

================================================================================
                         AUTHENTICATION HEADER
================================================================================

For all protected routes, include this header:

Authorization: Bearer {your_token_here}

Example:
Authorization: Bearer 5|d6kjPjOtcDCWPDhn2iaq6leU5OFXURmOnSL8f5cI54e81c0a

================================================================================
                           ORDER STATUSES
================================================================================

1. pending     → Order placed, waiting for processing
2. processing  → Order is being prepared
3. shipped     → Order has been shipped
4. delivered   → Order delivered to customer
5. cancelled   → Order was cancelled

================================================================================
                            USER ROLES
================================================================================

1. customer (default) → Can browse, cart, order, view own orders
2. admin              → Can do everything + update order statuses
